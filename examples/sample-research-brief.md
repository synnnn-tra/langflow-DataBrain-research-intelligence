# Sample research brief (illustrative)

> **Important:** This is a demonstration of the intended report structure. It is not a result captured from a live DBRI run, and it does not claim to contain verified market research or external-source citations.

## Research question

What should an Indonesian small business evaluate before adopting an AI customer-support assistant?

## 1. Executive summary

A small business should evaluate whether an assistant can handle a clearly bounded set of customer-support tasks, integrate with its existing channels, protect customer information, and escalate uncertain or sensitive requests to a person. A pilot should measure resolution quality and operational impact before wider deployment.

**Evidence status:** The points below are evaluation prompts and general considerations. They are not quantified findings from a market study.

## 2. Scope

- **Audience:** small-business owners and operations leads.
- **Decision:** whether to run a limited pilot.
- **Out of scope:** vendor rankings, current pricing comparisons, and claims about market share.
- **Evidence needed:** business-specific inquiry logs, vendor documentation, security terms, and pilot measurements.

## 3. Evaluation areas

| Area | Questions to investigate | Evidence to collect |
| --- | --- | --- |
| Use-case fit | Which recurring questions can be answered safely? Which require a human? | Sample inquiry set, escalation rules, test outcomes |
| Integration | Can the assistant connect to the actual support channels and approved data? | Vendor documentation, integration test |
| Answer quality | Does it answer correctly, abstain when uncertain, and cite approved sources? | Labelled test set and review rubric |
| Privacy and security | What data is stored, who can access it, and how can it be deleted? | Privacy terms, retention settings, access-control review |
| Operations | Who monitors failures and updates approved content? | Ownership plan, alert process, update schedule |
| Economics | Does the pilot save enough staff time to justify total cost? | Baseline and pilot time/cost measurements |

## 4. Risks and mitigations

- **Incorrect answers:** limit the initial scope, test against known examples, and add human escalation.
- **Outdated information:** define content owners and a refresh process.
- **Sensitive data exposure:** minimize collected data and review access, retention, and vendor terms.
- **Unclear value:** compare results with a measured baseline instead of assuming time savings.

## 5. Example pilot metrics

Set baselines before launch; choose thresholds with the business rather than inventing universal targets.

- Correct resolution rate on a reviewed test set.
- Escalation rate for ambiguous or sensitive questions.
- Human correction rate.
- Median response latency.
- Staff time spent per resolved inquiry.
- User satisfaction from a small, clearly described sample.

## 6. Evidence register

No external sources were consulted for this illustrative example. Before using it for a real decision, add source records and document which claims each source supports.

| Source | Status |
| --- | --- |
| Vendor technical documentation | To be collected |
| Privacy and retention policy | To be collected |
| Business inquiry baseline | To be measured |
| Pilot evaluation results | To be measured |

## 7. Recommendation

Run a small, human-supervised pilot only after defining the approved knowledge base, escalation behavior, data-handling rules, and evaluation metrics. Expand the deployment only if measured results meet the business's pre-agreed thresholds.

## 8. Limitations

This document illustrates structure only. It does not compare specific vendors, establish market trends, provide legal advice, or demonstrate the current DBRI workflow's runtime behavior.
